# Politique de sécurité

*[English below](#security-policy-english)*

## Signaler une vulnérabilité

**N'ouvrez pas d'issue publique** pour une faille de sécurité : tant qu'elle n'est pas
corrigée, la décrire en public expose toutes les instances installées.

Utilisez le signalement privé de GitHub : onglet **Security**, bouton
**[Report a vulnerability](https://github.com/manganate006/openlmnp/security/advisories/new)**.
L'avis n'est visible que de vous et des mainteneurs jusqu'à sa publication, et vous pouvez y
joindre un correctif.

Si vous n'avez pas de compte GitHub, écrivez à **contact@openlmnp.fr** avec « Sécurité » dans
l'objet.

Un rapport utile précise :

- la version concernée (affichée dans l'application, ou `version.json`) ;
- le type de faille et le composant touché ;
- les étapes pour la reproduire, idéalement avec une preuve de concept ;
- l'impact que vous en attendez (données d'un autre utilisateur, exécution de code…).

## Ce qui se passe ensuite

- **Accusé de réception** sous 7 jours.
- Échange dans l'avis privé le temps de confirmer et de corriger.
- Publication d'une version corrigée, puis de l'avis, qui vous crédite si vous le souhaitez.

OpenLMNP est maintenu par une petite équipe : ces délais sont indicatifs, pas contractuels.

## Versions prises en charge

Seule la **dernière version publiée** reçoit les correctifs de sécurité. Mettez à jour avant
de signaler, la faille est peut-être déjà corrigée.

# Security policy (English)

**Do not open a public issue** for a security vulnerability. Report it privately through
GitHub: **Security** tab, **[Report a vulnerability](https://github.com/manganate006/openlmnp/security/advisories/new)**.
Without a GitHub account, email **contact@openlmnp.fr** with "Security" in the subject.

Please include the affected version, the vulnerable component, reproduction steps and the
expected impact. We acknowledge reports within 7 days (indicative). Only the latest release
receives security fixes.
